# Feature Specification: Teams 共通バックエンド

**Feature Branch**: `main` / **Created**: 2026-10-26 / **Status**: Approved for implementation

**Input**: 同じバックエンドで Teams を利用可能にする。分割・実装判断は委任。

## User Scenarios & Testing

### US1 — Teams で根拠付きのまとめを読む (P1)

標準チャネルでボットをメンションすると、同じスレッドの概要・決定・未決定・ToDo・問いを返信する。
親投稿でのメンションはその投稿のスレッドを対象にする。

**Independent Test**: 合成した親投稿と複数ページの返信から、検証済み根拠へのリンク付き結果を得る。

1. 正しい認証・許可された組織とチームのメンションだけを受け付ける。
2. 未認証・別組織・未許可チーム・ボット自身・メンションなしの投稿では分析しない。
3. 編集・削除・再送・同時実行時も別チャネルや Slack へ書き込まない。
4. 不完全な履歴を完全取得と表示しない。読み取り不能は利用者に説明する。

### US2 — 期間の Findings を読む (P2)

自然文または `findings N` でチャネル全体の期間内の投稿・返信を振り返る。

**Independent Test**: 期間前の親への期間内返信も含め、期間外の発言を根拠にしない。

### Edge Cases

- HTML 本文、ユーザーのメンション、同一時刻の異なるメッセージ、ページング循環、429/5xx、権限不足。
- 過大な履歴や返信は上限を守り、履歴上限超過は分析を中止する。
- 長文の結果は安全なサイズに分割し、能動返信は認証済みの会話参照だけを使う。

## Requirements

- **FR-001**: 認証済みの標準チャネルメンションを非同期に処理する。
- **FR-002**: 親と全返信を取得し、ボット・削除済み・システム投稿を分析から除く。
- **FR-003**: Slack と同じ抽出・根拠検証・決定判定・意図解釈・Findings を使う。
- **FR-004**: すべての結果項目に検証済み根拠リンクか要確認を表示する。
- **FR-005**: 組織・チーム・チャネル・スレッド・サービスで保存とロックのキーを分離する。
- **FR-006**: 導入チーム限定の権限を基本とし、設定不足では起動を拒否する。
- **FR-007**: 本文・秘密・取得先URLの機密クエリをログへ残さない。
- **FR-008**: Slack の既存動作・デプロイ既定値を維持する。
- **FR-009**: Teams 初版は返信と分析結果の保存まで。ToDo の登録・完了・リマインド、canvas 相当の外部記録は未対応であることを返信と手順に明示する。

### Key Entities

- 会話参照: 組織、チーム、チャネル、スレッド、受信イベント、返信先。
- 分析対象: サービスごとに分離した状態と参加者、根拠メッセージの対応。

## Success Criteria

- **SC-001**: 合成会話でメンション受付から同一スレッド返信まで一連の検証が成功する。
- **SC-002**: 不正な認証・組織・チーム・返信先のケースで外部読み取り・投稿は0件。
- **SC-003**: 既存 Slack の全ローカル検証が成功する。

## Assumptions

- Microsoft の商用クラウド、単一組織、標準チャネルを初版の対象とする。
- 管理者がアプリ登録・Azure Bot・Teams アプリ導入・同意を行う。
- 本番デプロイ、実 Teams、実 AI、実 Firestore の検証は利用者が行う。
