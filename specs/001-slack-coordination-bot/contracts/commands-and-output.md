# Contract: メンションの文法と出力の形式

## 文法（commands/parse.ts）

メンション `<@BOT>` を除いた本文を、前後の空白を除き、全角を半角にして解析する。

| 入力の例 | command | 備考 |
|---|---|---|
| `まとめ`、`summary`、`要約` | summarize | |
| `canvas`、`キャンバス` | canvas | スレッドの中だけ。チャネルで直接呼ばれたら案内を返す |
| `todo`、`ToDo`、`タスク` | todo | |
| `findings`、`findings 30日`、`findings 30`、`振り返り 14日` | findings | 既定は 30、上限は 90（超えたら 90 にして、その旨を添える） |
| それ以外、空 | — | 使い方を返信する |

## 返信（Block Kit、slack/render.ts）

まとめ（summarize と todo の共通部分）:

```
📋 調整のまとめ（前回から: 追加 2 / 変更 1 / 完了 1）
*決定事項*
• 定例の日程: 10/28(火) 15:00  <link|根拠>  🆕
*未決定事項*
• 会場: オンライン / 対面 — 回答待ち: @鈴木, @高橋  <link|根拠>
*ToDo*
• 会議室を予約する — @田中 / 期限 10/27(月)  <link|根拠>
*未解決の問い*
• 予算の上限は?  <link|根拠>
⚠️ 要確認: 根拠を確かめられなかった項目には ⚠️ を付けています
```

- 前回からの変化は、見出しの後の件数と、項目の印（🆕 追加、✏️ 変更、✅ 完了）で示す。
- 項目がなければ「まとめる調整事項は見つかりませんでした」と返信する（US1 の 5）。
- Block Kit の上限（50 ブロック、1 つの section の本文は 3,000 文字）を超える場合は、分類ごとに分割し、続きの返信にする。

ToDo の一覧（todo）: まとめの ToDo 部分と同じ形で、各項目に完了のボタン（`action_id = "todo_done"`、`value = todoId`）を付ける。

findings:

```
🔎 Findings（#channel、直近 30 日）
*テーマ: 会場の選定*
• オンライン開催の要望が繰り返し出ている  <link|1> <link|2> <link|3>
...
```

## canvas の節（slack/canvas.ts）

節は「目印付きの h2 の見出し」と「本文の 1 ブロック」の 2 ブロックでできる（R8）。本文は行末の空白 2 つ（`  \n`）で改行してつなぎ、空行を入れない。

```markdown
## 調整: <topic の題名か、スレッドの最初の発言の先頭 30 文字> 〔arb:<threadTs>〕

最終更新: 2026-10-24 14:03（@呼んだ人） · [スレッド](<permalink>) 〔arb:<threadTs>〕  
**決定事項**  
• ...  
**未決定事項**  
• ...  
**ToDo**  
☐ 会議室を予約する — ![](@U123) / 期限 10/27
```

- 目印 `〔arb:<threadTs>〕` は見出しと本文の両方に入れる（本文のブロックを `canvases.sections.lookup` で引くため）。
- 本文の各行は 1 行にする（項目の中の改行は空白に置き換える）。行頭が `#`・`-`・`*`・`>`・数字と `.` などの markdown の記号にならないよう、項目は `• ` か `☐ ` で始める。
- h3、チェックリスト（`- [ ]`）、引用、`<br>` は使わない（h3 は別のブロックになり、チェックリストは普通の箇条書きになり、引用は行がつながり、`<br>` は文字のまま出る）。
