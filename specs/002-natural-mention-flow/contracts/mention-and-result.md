# Contract: メンションと結果

| メンション本文 | 解釈 | 動作 |
|---|---|---|
| 空、`まとめ`、`summary`、`要約` | summary | 概要と調整項目。スレッド内では自動 ToDo/canvas を判定 |
| `この会話をまとめて` | summary | 自然文で同じ一括処理を依頼 |
| `見るだけ`、`登録しないでまとめて` | summary with suppression | 返信のみ。抑止した操作を明記 |
| `先週の動きを振り返って` | findings, 前週 | JST の前週月曜0時〜今週月曜0時未満 |
| `今週の振り返り` | findings, 当週 | JST の今週月曜0時〜現在 |
| `この2週間の学びは？` | findings, 直近14日 | 実際の対象期間を表示 |
| `今月の振り返り` | findings, 当月 | JST の月初0時〜現在 |
| `振り返って` | findings, 期間省略 | 直近30日 |
| 従来の `todo`（`タスク`） / `canvas`（`キャンバス`） / `findings 30日`（`振り返り 14日`） | 既存の明示操作 | 従来の操作を維持。canvas はスレッド内で呼ぶ |
| 意図や期間が曖昧 | clarify | 副作用を実行せず短い確認を返信 |

すべての依頼は ingress が worker に積み、受付の 👀 を付ける。空メンションと既知コマンドはコードで確定し、それ以外は worker がメンション本文だけから意図を抽出する。会話本文中の命令で処理や投稿先を変更しない。

summary は根拠付き概要（最大3項目）、取得件数と最初・最後の投稿時刻、決定・未決定・ToDo、要確認を返信する。調整事項がなくても概要と取得範囲を示す。投稿0件なら概要と投稿時刻は表示せず「投稿0件」と対象範囲を示す。チャネル直下では直近7日を対象に返信し、自動 ToDo 登録と canvas 更新は行わない。

スレッド内の自動登録は、未完了、担当者のユーザー ID が参加者に存在、要確認でない、根拠が1件以上で検証済み、利用者による抑止なしをすべて満たす ToDo に限る。決定・未決定・登録対象 ToDo があれば canvas の管理節を作成・更新し、既存節は内容が空になっても更新する。返信には登録件数、自動登録対象外、canvas の作成・更新・対象なし・失敗、抑止した操作を示す。登録した ToDo は完了ボタン付きの一覧でも返信する。

`先週`・`今週`・`今月` は上表の JST の暦区切り、`直近N日`・`このN週間` は現在から遡る期間とする。取得区間は開始以上・終了未満。期間省略は30日、最大90日に制限し、実際の対象期間と、制限した場合はその旨を表示する。

投稿先は依頼元のチャネル・スレッドに固定する。同じ依頼の再試行は7日 TTL の段階状態と投稿済み返信を確認して復元し、同じ ToDo と canvas 節を重複させない。別メンションでの再実行も既存項目を更新し、完了状態を維持する。部分失敗は返信で示し、返信の再送前に既存投稿を確認して重複を抑える（Slack への投稿と状態保存は原子的でなく、返信の絶対的な一意性は保証しない）。
