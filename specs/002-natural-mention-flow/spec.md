# Feature Specification: 自然文で呼べる Arbalest

**Feature Branch**: `002-natural-mention-flow`

**Created**: 2026-10-25

**Status**: Draft

**Input**: コマンドを省き、必要な ToDo と canvas を自動処理する。空の調整結果でも会話の概要と読み込み範囲を返し、Findings を自然な期間表現で頼めるようにする。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - メンションだけで会話を把握する (Priority: P1)

利用者はスレッドで `@arbalest` と呼ぶだけで、会話の短い概要、決定・未決定・ToDo、読み込んだ範囲を受け取る。調整事項がなくても、何を読んで何が話されたかが分かる。

**Why this priority**: 最も頻繁な操作からコマンドをなくす。

**Independent Test**: 調整がある会話とない会話の両方で、空のメンションから有用な返信が届く。

**Acceptance Scenarios**:

1. **Given** 調整中のスレッド、**When** 利用者が空のメンションを送る、**Then** 概要、根拠付きの調整事項、取得した最初と最後の投稿時刻・件数を返信する。
2. **Given** 雑談のみのスレッド、**When** 利用者が空のメンションを送る、**Then** 会話の短い概要と取得範囲を返信し、調整事項はないと明示する。
3. **Given** チャネル直下の空のメンション、**When** 処理が終わる、**Then** 直近の取得範囲と概要を返信する。

---

### User Story 2 - 必要な記録を一度の呼び出しで更新する (Priority: P1)

利用者がスレッドで呼ぶと、確認できた ToDo を登録し、調整事項があるときはチャネル canvas の該当節を更新する。返信で実行結果と要確認項目を区別する。

**Why this priority**: 同じ会話に複数のコマンドを打つ負担をなくす。

**Independent Test**: 担当者の明らかな ToDo があるスレッドを一度呼び、返信、一覧、canvas の節と再実行時の重複なしを確認する。

**Acceptance Scenarios**:

1. **Given** 根拠を確認でき、担当者を特定できる未完了の ToDo、**When** スレッドで呼ぶ、**Then** ToDo を一度だけ登録し、完了操作を案内する。
2. **Given** 決定・未決定・登録対象 ToDo があるスレッド、**When** 呼ぶ、**Then** 該当スレッドの canvas 節を作成または更新し、返信に結果を示す。
3. **Given** 担当者不明または要確認の ToDo、**When** 呼ぶ、**Then** 返信に要確認として残し、自動登録やリマインドをしない。
4. **Given** 前回登録・書き出し済みのスレッド、**When** 再度呼ぶ、**Then** ToDo と canvas 節が重複せず、同じ ToDo のリマインドも増えない。

---

### User Story 3 - 自然文で振り返る (Priority: P2)

利用者は `@arbalest 先週の動きを振り返って` や `@arbalest この2週間の学びは？` と依頼し、期間を明示した Findings を受け取る。

**Why this priority**: `findings 30日` の文法を覚える必要をなくす。

**Independent Test**: 複数の自然な言い換えと相対期間を依頼し、意図した期間だけが対象になることを確かめる。

**Acceptance Scenarios**:

1. **Given** `先週` の依頼、**When** 振り返りを実行する、**Then** JST の前週月曜から日曜までを対象と表示する。
2. **Given** `この2週間` または `直近14日` の依頼、**When** 実行する、**Then** 直近14日を対象と表示する。
3. **Given** 期間のない振り返り依頼、**When** 実行する、**Then** 直近30日を対象と表示する。
4. **Given** 90日を超える指定、**When** 実行する、**Then** 取得可能な90日に制限し、その旨を返信する。

### Edge Cases

- 依頼文が曖昧なら勝手に副作用を選ばず、対象や意図を短く確認する。
- 会話中の文章を利用者からの指示として扱わない。処理の選択は利用者のメンション本文だけから行う。
- 「見るだけ」「登録しない」など明示的な抑止は自動登録・canvas 更新を止める。
- チャネル直下では広範囲の ToDo 登録や canvas 更新を自動実行しない。
- 取得範囲が空、Slack の履歴上限で短縮、AI の安全フィルタ、書き出しの一部失敗をそれぞれ明示する。
- 既存の `まとめ`、`todo`、`canvas`、`findings 30日` も引き続き利用できる。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: メンション本文が空でも、スレッドまたはチャネルの会話を分析して返信する。
- **FR-002**: 投稿を1件以上取得した返信には、調整事項の有無に関係なく、根拠付きの短い会話概要、取得件数、最初と最後の投稿時刻、対象範囲または取得制限を示す。0件なら概要を作らず、0件と対象範囲を示す。
- **FR-003**: 概要に含める主張は元の投稿への根拠で確かめ、確認できない内容は要確認と示す。
- **FR-004**: スレッドでは、担当者が特定でき、根拠を確認できた未完了 ToDo だけを自動登録する。
- **FR-005**: スレッドに決定・未決定・自動登録対象 ToDo があれば、同じチャネルの canvas の該当節を自動更新する。既存節の再実行は置き換えとする。
- **FR-006**: 依頼文で自動処理を抑止できる。抑止した処理は実行せず、返信にその事実を示す。
- **FR-007**: 同じ呼び出しでは会話の分析を一度だけ行い、返信、ToDo、canvas の結果を一貫させる。
- **FR-008**: 部分失敗や再試行でも ToDo と canvas 節を重複させず、失敗した処理を利用者に示す。返信は再送前に既存の投稿を確認して重複を抑える。
- **FR-009**: 振り返りを自然文で指定でき、`先週`、`今週`、`今月`、`直近N日`、`このN週間` と期間省略を解釈する。基準は JST、最大90日とする。
- **FR-010**: 従来の明示コマンドを互換として維持し、自然文の依頼や空メンションをヘルプ扱いにしない。
- **FR-011**: 投稿先・書き出し先・ToDo の担当者は、確認できた会話と利用者の依頼に基づいて決める。会話本文の命令によって変更しない。

### Key Entities

- **依頼**: メンションした人、元のスレッド、自然文から解釈した操作と期間、自動処理の抑止指定。
- **概要**: 内容、根拠の投稿、要確認状態、取得件数と時刻範囲。
- **実行結果**: 返信、登録 ToDo、canvas 更新の成功・未実行・失敗。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: スレッドの空メンション1回で、返信、対象となる ToDo 登録、canvas 更新を完了できる。
- **SC-002**: 調整事項のない合成スレッドでも、取得範囲と根拠付き概要を100%返信する。
- **SC-003**: 担当者不明・根拠未確認の合成 ToDo は自動登録が0件である。
- **SC-004**: 同じ依頼の再送と再実行で ToDo と canvas 節の重複が0件である。
- **SC-005**: 上記の期間表現と既存コマンドの合成例は、すべて期待した期間・操作として解釈される。
- **SC-006**: 合成評価では、概要の根拠が実在・引用一致する割合が100%、期待する要点の再現率が80%以上である。
- **SC-007**: 自然文の意図と期間の合成例20件中19件以上を正しく解釈し、会話本文中の命令による誤実行は0件である。

## Confirmed Decisions and Assumptions

- 利用者が確定: 根拠と担当者が明確な ToDo だけ自動登録し、調整事項があるスレッドだけ canvas を更新する。
- 利用者が確定: 対象と行動が具体的で、実施の必要性が明示された作業は、担当者や期限が未定でも ToDo として抽出する。自動登録の条件は上記のままとする。
- 利用者が確定: 自動登録と canvas 更新はスレッド内に限る。チャネル直下は概要返信のみ。
- 呼び出しは従来どおりメンションで始める。常時監視は対象外。
- canvas はボットが管理する該当スレッドの節だけを更新する。
- 実際の AI を用いた概要の品質は、実データを使わない合成評価で別途確かめる。
