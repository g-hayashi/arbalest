# Research: 自然文で呼べる Arbalest

## R1. 依頼文の解釈

- **Decision**: 空メンションと旧コマンドはコードで確定する。その他の自然文はメンション本文だけを構造化抽出し、worker で `summary` / `findings` / `clarify` と抑止指定に分類する。操作を実行するかはコードが検証する。
- **Rationale**: 定型語を増やすだけでは言い換えに弱い。会話本文を混ぜるとプロンプトインジェクションで操作を変えられる。
- **Alternatives**: ingress で AI を呼ぶ（ack が遅くなる）、会話全体を意図分類に渡す（会話の命令と混ざる）。

## R2. 自動処理

- **Decision**: スレッドの一括ジョブで分析を1回行う。未完了で担当者が特定でき、根拠検証済みの ToDo を登録する。決定・未決定・登録対象 ToDo があれば canvas の管理節を更新する。既存の節がある場合は状態が空になっても更新する。チャネル直下は返信のみ。
- **Rationale**: 独立した既存ジョブを連続実行すると分析と返信が重複する。担当未定・要確認の登録は誤通知につながる。
- **Alternatives**: すべて登録して依頼者へリマインド（誤登録が増える）、canvas を毎回作る（空節が増える）。

## R3. 概要と取得範囲

- **Decision**: AI が短い概要の候補と根拠 ID を抽出し、コードで根拠の実在・引用を確認する。0件なら概要を作らない。件数・最初/最後の時刻・チャネルの7日窓・履歴上限は取得結果からコードで表示する。
- **Rationale**: 既存の調整項目だけでは雑談や情報共有の概要を作れない。単なる件数だけでは利用者の要求を満たさない。
- **Alternatives**: 先頭文の抜粋（内容を要約できない）、根拠なしの自由文（憲章IIIに違反）。

## R4. 振り返りの期間

- **Decision**: `先週`/`今週`/`今月` は JST の暦区切り、`直近N日`/`このN週間` は現在から遡る日数とする。開始・終了を検証してから取得する。最大90日へ制限し、実際の期間を表示する。
- **Rationale**: `先週` を直近7日と扱うと期待からずれる。相対表現の意味をコードで固定できる。
- **Alternatives**: AI に日時を直接決めさせる（ぶれがある）、日数のみ対応（自然文の利点が小さい）。

## R5. 再試行と部分失敗

- **Decision**: stable な ToDo ID と canvas marker を維持する。`processed_events/{taskName}` に7日 TTL の段階状態と返信 ts を保存する。返信は処理結果を1件の最終メッセージにまとめ、投稿済みならその ts を保存して更新する。投稿成功直後で ts の保存前に失敗した場合は、再送前に元のスレッドの投稿を確認して重複を抑える。失敗した操作は利用者に示す。
- **Rationale**: Slack/Firestore の途中失敗後の再試行では副作用が重複しうる。Slack への投稿と Firestore 保存を原子的にはできないため、返信の絶対的な一意性は保証しない。
- **Alternatives**: 全工程を再実行（通知の重複）、失敗を隠す（利用者が状態を誤認）。

## R6. 合成評価

- **Decision**: 根拠の実在・引用一致率は100%、概要の期待要点の再現率は80%以上、依頼意図と期間は20件中19件以上の正解とする。会話本文中の命令による副作用は0件とする。
- **Rationale**: 意図誤認は誤登録や期間違いを生む。概要は根拠の正確さと内容の網羅を別に測る。
- **Alternatives**: 目視だけの判定（再現性がない）、表面的な文字列一致だけの採点（言い換えを不当に落とす）。
