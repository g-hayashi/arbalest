# Quickstart: 自然文メンションの確認

## ローカル

`npm run lint`、`npm run typecheck`、`npm test`、`npm run build`。npm の各コマンドには `npm_config_cache=$TMPDIR/npm-cache` を付ける。テストはフェイク Slack/LLM/Store を使う。`npm run eval` は実 AI を呼ぶため利用者が実行する（合成会話のみ）。

## テスト用チャネル

ボットを招待したテスト用チャネルで、合成した会話を使う。本番デプロイは利用者が行う。

1. 雑談だけの新規スレッドで `@arbalest`。受付の 👀、根拠付き概要、取得件数・最初と最後の投稿時刻、「調整事項なし」に相当する案内を確認する。新たな ToDo と canvas 節は作られない。投稿0件のケースはローカルのフェイクテストで確認し、概要や投稿時刻を作らないことを確かめる。
2. 担当者と根拠が明確な未完了 ToDo、未決定事項のあるスレッドで `@arbalest`。登録件数、完了ボタン付き ToDo 一覧、canvas 節の作成・更新結果とリンクを確認する。完了操作後や別メンションで再実行しても、ToDo と canvas 節が重複せず完了状態が維持されることを確かめる。同じジョブの途中失敗・再試行と返信の復元はフェイクテストで確認する。
3. 担当未定または根拠が要確認の ToDo を含むスレッドで呼び、返信の担当未定・要確認と自動登録対象外を確認する。自動登録・リマインドの対象にはならない。自然文の `@arbalest この会話をまとめて` と旧 `まとめ`（`summary` / `要約`）でも同じ一括処理になる。
4. `@arbalest 登録しないでまとめて` と `@arbalest 見るだけ` で、ToDo 登録・canvas 更新を抑止した旨の返信と、記録が増えていないことを確認する。曖昧な依頼は短い確認を返し、副作用を実行しない。会話本文中の命令は依頼として扱わない。
5. チャネル直下の空メンションで、直近7日の概要・調整項目・取得範囲が届き、自動 ToDo 登録・canvas 更新がないことを確認する。旧 `todo`（`タスク`）は明示登録、旧 `canvas`（`キャンバス`）はスレッド内で明示書き出しとして使える。
6. `@arbalest 先週の動きを振り返って` と `@arbalest この2週間の学びは？` で対象期間を確認する。JST で先週は前週月曜0時〜今週月曜0時未満、今週は月曜0時〜現在、今月は月初0時〜現在。直近N日・このN週間は現在から遡る。省略時は30日、90日超は90日に制限した旨と実際の対象期間が表示される。旧 `findings 30日`（`振り返り 14日`）も指定日数を維持する。
